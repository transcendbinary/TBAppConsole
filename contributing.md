# Contributions:
please familarise yourself with the codebase and design of the app.

## take into account the following design constraints.
- the app should feel native and clear the console between every navigation. 
- use the same loading method for everything which needs to load (clear screen, print loading, append a dot every quarter second, clear screen, print content)
- use the same menu system (switch statment for each menu, method for every menu item - always use getKey and ensure the action is instant and doesnt require pressing enter)

## Before submitting PR
- check the issues page for any bugs you can fix or requests you can implement - ensure you update the issues
- manually test every case your changes can result in. dedicated unit tests are not required, but ensure expected functionality proper error handling.
- ensure the version number matches the latest version of the current release, do not increment it.

## once everything is correct and working
- submit a PR with a detailed message and reference any applicable issues
- we will test and merge your changes and push a new version release.
